# AGENTS.md

Guidance for AI coding agents and human contributors. Details: [CONTRIBUTING.md](CONTRIBUTING.md),
[docs/architecture.md](docs/architecture.md), [docs/adr/](docs/adr/README.md).

## Layout

```
core/agent/        generate-check-repair loop (run, modify, save), prompts.py
core/llm.py        OpenAI-compatible client; core/models.py: PartSpec, Issue (pydantic)
core/config.py     config.yaml + LINGENIOUS__SECTION__KEY overrides
core/sandbox/      AST allow-list + subprocess execution of generated scripts
core/checks/       L1/L2/L3 rules (@rule), features.py (shared B-Rep queries)
core/render/  core/drawing/    PNG render, three-view drawing (HLR, DXF/PDF/PNG)
web/server/        FastAPI backend; web/ui/: React + three.js; web/landing/: static page
adapters/feishu_bitable/       optional demo adapter (lark-cli)
eval/              task sets, reference solids, ground truth, runner, report, results
tests/             pytest; docs/: user, contributor and process-engineer docs
config.yaml        defaults (LLM, rounds, sandbox, DFM thresholds)
```

## Commands

CadQuery is only installed in the Docker images; do not try to install it locally.

```bash
make test        # pytest in the dev image (make cov for coverage)
make lint        # ruff check + mypy in the dev image
make ui-check    # web/ui typecheck, eslint, vitest (Node 22, after make ui-install)
make help        # all targets
```

Tests that need no CadQuery run locally too, e.g. `python3 -m pytest -q tests/test_feishu_adapter.py`.
Slow reference-solid sweeps are marked `slow` (`pytest -m "not slow"`). Nothing in the test suite calls a
real LLM; tests use fakes. Evaluation runs (`eval.runner`, `make eval-dfm`) do call the LLM and cost money.

## Conventions

- **Deterministic checks never call the LLM.** Pass/fail is decided only by code in `core/checks`
  ([ADR 0001](docs/adr/0001-llm-designs-kernel-judges.md)). Issue messages carry measured values; hints are
  generated by the rule.
- **Every rule has a positive and a negative test** (triggers / does not trigger), and is documented in
  [docs/dfm-rules.md](docs/dfm-rules.md). New thresholds state their source or are labeled "rule of thumb".
- **Docs:** keep `README.md` and `README.zh-CN.md` in sync; update the matching file in `docs/` when
  behaviour, config keys, API or outputs change; record significant design changes as a new ADR.
- **Results:** never edit `eval/results*` by hand; regenerate with `eval.runner` / `eval.report` and keep
  interpretations honest (small samples, noise, one model).
- **No secrets:** keys come from environment variables (`.env`, git-ignored). Pre-commit runs
  `scripts/scan_secrets.py`.
- **No environment-specific information** in code, docs or commits: no personal hosts, IPs, Docker contexts,
  mirror URLs or local paths. Use placeholders such as `<your-key>` or `<host>`.
- Keep diffs focused; `ruff format` is not enforced, so do not reformat unrelated code.

Personal notes go in `AGENTS.local.md` or `CLAUDE.local.md` (both git-ignored).
